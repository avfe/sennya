# sennya

[English](README.md) | **Русский**

Быстрый терминал на Rust с GPU-рендерингом (wgpu/Metal). Сессии живут в отдельном фоновом процессе,
поэтому закрытие окна, `kill -9` или его падение не убивает ни один шелл. Даже если умер сам daemon
(или перезагрузился Mac), терминалы восстанавливаются с историей и раскладкой. Терминал сделан для
работы с AI-агентами: сессии Claude Code отслеживаются и возобновляются после перезапусков, а сам
Claude управляет терминалом через CLI.

Основная платформа — macOS, сборки под Windows тоже работают (см. [Windows](#windows)).

## Установка

**Из релиза.** Скачайте архив для своей системы на странице
[Releases](https://github.com/avfe/sennya/releases):

- **macOS**: `Sennya-macos-universal.zip`. Распакуйте и дважды кликните `install.command`. Он кладёт
  `Sennya.app` в `/Applications`, делает команду `sennya` доступной в `PATH` и ставит skill для
  Claude Code. Приложение не нотаризовано, поэтому при первом открытии `Sennya.app` напрямую
  используйте правый клик → «Открыть».
- **Windows**: `sennya-windows-x64.zip`. Распакуйте и выполните
  `powershell -ExecutionPolicy Bypass -File install-windows.ps1`. Программа ставится в
  `%LOCALAPPDATA%\Programs\sennya`, добавляется в `PATH` и в меню «Пуск».

**Из исходников** (macOS, нужен Rust):

```sh
./scripts/install-macos.sh
```

Скрипт собирает `Sennya.app`, кладёт его в `/Applications`, делает команду `sennya` доступной
в `PATH` и устанавливает skill для Claude Code. Откатить:
`rm -rf /Applications/Sennya.app /opt/homebrew/bin/sennya ~/.claude/skills/sennya`.

**Skill для Claude Code ставится при любой установке.** Он лежит в `~/.claude/skills/sennya` и учит
Claude открывать терминалы, запускать задачи рядом с собой, писать профили и менять настройки.
Daemon обновляет его при каждом старте, если есть папка `~/.claude`; вручную — `sennya install-skill`.

```
sennya            открыть окно (daemon стартует сам)
sennya --help     все команды CLI
sennya kill       остановить daemon и все терминалы
```

После обновления окно предложит перезапустить daemon. Терминалы вернутся в тех же папках
с историей, чаты Claude Code продолжатся, остальные запущенные в них программы остановятся.

## Возможности

- **Два режима** (`⌘G` — переключение):
  - **Grid**: все терминалы страницы видны сразу. Новый терминал сам встраивается в сетку,
    разделители двигаются мышью, панели перетаскиваются за заголовок (к краю другой панели или
    в центр, чтобы поменять их местами).
  - **Tabs**: вертикальные вкладки слева, справа один терминал на весь экран.
- **Страницы**: отдельные сетки терминалов (`⌘N`, `⌘1…9`, `⌥⌘[` / `⌥⌘]`). Терминал можно перетащить на
  вкладку страницы или в её заголовок в сайдбаре. Если страниц больше, чем помещается, вкладки
  прокручиваются вбок.
- **Раскладки страницы**: Grid / Columns / Rows / Main + stack / Manual. Grid, Columns и Rows
  перестраиваются автоматически; если подвинуть разделитель, страница переходит в Manual.
- **Области**: правый клик по панели → «New terminals open in this area». После этого `⌘T` добавляет
  терминалы в группу этой панели.
- **Поиск**: `⌘F` ищет в текущем терминале, `⌘⇧F` — по истории всех терминалов на всех страницах,
  `⌘P` — быстрый переход к терминалу по названию или папке (и запуск профилей).
- **Буфер обмена**: `⌘C` / `⌘V`; bracketed paste с защитой от подмены; подтверждение перед вставкой
  нескольких строк в «голый» шелл.
- **Скриншоты и картинки**: `⌘V` с картинкой в буфере (например, после `⌘⌃⇧4`) сохраняет её в PNG и
  вставляет путь. Claude Code показывает такую вставку как `[Image #1]`. `⌃V` уходит в программу как
  есть, поэтому родная вставка картинок в Claude Code тоже работает.
- **Drag & drop файлов** в окно вставляет экранированные пути.
- **Кликабельные ссылки**: `⌘`+клик. Работают обычные URL (в том числе перенесённые на следующую
  строку) и OSC 8 hyperlinks.
- **Shift+Enter** вставляет перевод строки в Claude Code без отправки сообщения.
- Колесо мыши, выделение (двойной клик — слово, тройной — строка, `⌥`+drag — блок), mouse reporting
  для vim/htop, focus events, «natural text editing» на macOS (`⌥←`, `⌘←`, `⌘⌫`), работа сочетаний
  на русской раскладке.
- Индикаторы активности и колокольчика на вкладках, переименование (`F2` или двойной клик).
- **Множественный выбор**: зажмите терминал в списке (или `⌘`+клик) — появятся галочки и панель
  «Close N / Move to / All / Done». `Esc` выходит из выбора.
- **Сворачиваемые страницы** в сайдбаре (клик по заголовку страницы), свёрнутость запоминается.
- Сайдбар скрывается кнопкой `«` (показывается обратно `»`) или `⌘B`.
- Flat-дизайн: панели сетки без рамок и заголовков, разделены линией в 1 px, активная отмечена
  полоской сверху. Плашка «перетащить / развернуть / закрыть» появляется при наведении на верх панели.

## Профили

Профиль превращает одну горячую клавишу в рецепт: открывает терминал (вкладка, сплит, стопка или
новая страница) и набирает команды, дожидаясь между ними промпта или текста на экране. Например:
`ssh dev`, новая папка `task_{uuid}`, затем `claude` с задачей, которую вы введёте.

Создать профиль можно тремя способами, все в ⚙ → Profiles:

- **Редактор** (New profile… / Edit profiles…): имя, горячая клавиша, где открыть, папка и команды.
  Для каждой команды выбирается, когда её набрать: как только шелл готов, сразу после предыдущей,
  после промпта (`$`, `%`, `#`, `>`) или после появления текста. «Save and run» сразу пробует профиль.
- **Запись**: нажмите «Record from a terminal», наберите команды в активном терминале как обычно,
  затем «Stop and edit». Каждая команда становится шагом, который ждёт тот промпт, в котором её
  набрали. Пароли не записываются: терминал их не показывает.
- **Описать Claude**: рядом открывается Claude Code с начатым запросом. Опишите своими словами, что
  должен делать профиль, и Claude запишет его в конфиг через skill sennya.

Подстановки: `{uuid}` `{short}` `{words}` `{timestamp}` `{date}` `{time}` `{cwd}` `{cwd_name}` `{home}`
`{env:NAME}`. `{prompt:Вопрос}` спрашивается при запуске, `|q` экранирует значение для shell. Запуск:
горячая клавиша, `⌘P`, меню ⚙ → Profiles или `sennya run имя`. Профили хранятся как `[[profile]]`
в конфиге, так что их можно править и там.

## Агенты и Claude Code

- **CLI для агентов** (JSON): `sennya list / new / claude / run / send / read / focus / hide /
  show / close / layout / history / resume`. Внутри терминала sennya `current` означает этот
  терминал. Например, Claude сам открывает задачу рядом с собой:
  `sennya claude --near current --open stack --skip-permissions "текст задачи"`.
  Полная инструкция для агента: `sennya help agents` (это `AGENTS.md`).
- **Чаты Claude Code** (`⇧⌘H`): все разговоры с заголовками, папкой, веткой и временем; клик
  открывает `claude --resume <id>` в новом терминале. Терминал помнит, какой чат в нём шёл,
  а после перезапуска или падения daemon чат возобновляется сам (`persistence.resume_claude`) в том
  же режиме разрешений, в каком был (bypass остаётся bypass).
- **Скрытые терминалы** (`⇧⌘M` или «—» на плашке панели): продолжают работать, видны приглушёнными
  в сайдбаре и в полоске под сеткой с индикатором активности; клик возвращает их в сетку.
- **Несколько окон** (`⇧⌘N`): каждое окно показывает свою страницу и свой режим, раскладка общая.
- **Режим фокуса** (`⌃⌘F`): полноэкранный режим без сайдбара и панелей — только терминалы.
- Тема **true-black** (чистый чёрный для OLED) — в меню ⚙ → Theme.

## Серверы

На сервере может работать свой daemon sennya: тогда терминалы живут там и переживают обрыв
сети, сон ноутбука и перезапуск окна. Нужен только SSH, никаких UDP-портов, как у mosh.

```sh
sennya remote install dev   # один раз: поставить daemon на сервер (любой хост для `ssh`)
sennya remote dev           # открыть окно сервера; при обрыве оно переподключается само
```

- Окно проверяет связь каждые 2 секунды. Когда сеть пропадает (смена Wi-Fi, VPN, сон), оно
  замечает это примерно за 6 секунд и переподключается, как только сервер снова доступен. Все
  терминалы на месте: шеллы обрыва даже не заметили.
- Связь идёт обычным `ssh dev sennya proxy`, поэтому ключи, `~/.ssh/config` и jump-хосты работают
  как обычно. Вход должен быть без пароля: ключ или ssh-agent. По сети передаются только
  изменившиеся строки экрана.
- На Mac-сервер копируется готовый бинарник, на Linux daemon собирается из исходников
  (`--install-rust` поставит Rust через rustup, без sudo).
- В меню ⚙ → Servers есть список серверов из `[[remote]]` в конфиге и «Connect to a server…».

## Windows

`sennya.exe` — та же программа: daemon (сессии ConPTY через AF_UNIX-сокет), окно и CLI. Шелл по
умолчанию — PowerShell; `Ctrl+C` копирует, если есть выделение, и прерывает программу, если нет;
`Ctrl+V` вставляет. Собрать с Mac: `./scripts/build-windows.sh` (нужен
[llvm-mingw](https://github.com/mstorsjo/llvm-mingw)).

## Производительность

- Терминалы эмулирует daemon (`alacritty_terminal`). Окно получает кадры **только для видимых**
  терминалов и не больше ~140 раз в секунду, поэтому 50 открытых сессий почти ничего не стоят.
- В простое оба процесса потребляют 0% CPU: перерисовка происходит только по событиям.
- В тесте (debug-сборка) `seq 1 300000` обработался меньше чем за секунду. Пик CPU: окно 10%,
  daemon 55%, затем сразу 0%.

## Безопасность

- Сокет и все файлы приватные (`0700`/`0600`), daemon проверяет UID подключившегося процесса.
- Программы могут только записывать в буфер обмена (OSC 52), чтение запрещено.
- Bracketed paste нельзя «закрыть» изнутри вставляемого текста.
- Ссылки открываются только для http/https/file/ftp/mailto.
- Сохранение scrollback на диск можно выключить (`persistence.save_scrollback = false`).
- Если daemon пережил выход из учётной записи macOS, его терминалы теряют доступ к системным
  службам: DNS, связке ключей, проверке сертификатов. Окно это замечает и предлагает перезапуск.

## Настройка

`~/.config/sennya/config.toml` создаётся при первом запуске с комментариями и подхватывается
на лету. Там настраиваются шрифт (цепочка семейств), тема (11 встроенных, можно переопределить
любой цвет), шелл, переменные окружения, курсор, `option_as_alt`, поведение вставки картинок,
сохранение истории, профили и любые сочетания клавиш (`[keys]`). Тему можно сменить и через меню ⚙.

## Архитектура

```
 окно (winit + wgpu + egui)  ── Unix socket, postcard ──  daemon
   раскладка, ввод, рендер                                  PTY + alacritty_terminal на сессию
   только видимые панели                                    кадры видимых сессий, поиск,
                                                            автосохранение state.json + scrollback
```

- `src/daemon` — сессии, рассылка кадров, сохранение и восстановление.
- `src/gui` — окно, UI, клавиатура и мышь, рендер сетки.
- `src/model.rs` — модель страниц и дерева разбиений (общая для окна и daemon).
- `src/protocol.rs` — сообщения между процессами.
- `src/sys.rs` — то, что отличается между macOS/Linux и Windows.

Тесты: `cargo test` (юнит-тесты и e2e: настоящий daemon, шелл, `kill -9` и восстановление).
